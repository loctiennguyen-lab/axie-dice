# BUG-0007 — Màn Result và màn Pass nói khác nhau về Pass (tên, XP, phần thưởng)

- Mức: S2 (thông tin sai về tiền thưởng; server đúng, không ai nhận nhầm tiền).
- Thấy ở: UX hunt 27/10, dòng S2-1 (ảnh 02b/02c/04f so với 08d). Result hiện "Lunacia Pass Lv 2, +180 XP, Lv 2 pays 200 shard". Màn Pass hiện "Season Pass", 0/500 XP, LV 1 = 300 Shard, LV 2 = 1 ticket.
- Cái nào thật: màn Pass. Pass hiện tại là Pass v2 (`godot/assets/data/economy/pass_v2.json`, mùa s1, 30 level, level 1 cần 500 XP). Worker cũng đọc đúng file này (`worker/src/economy.js`: `passLevel`, `syncPassXp`, claim `pass`). Mùa 1 bắt đầu 3/11/2026, trước ngày đó mọi run đều cho 0 Pass XP.
- Nguyên nhân: thẻ Pass trong `ResultView._build_pass_card` còn đọc bảng cũ `ContentDB.BP_TRACK` qua `MetaState.bp_progress()` (tên "Lunacia Pass", XP kiểu cũ, "Lv N pays X shard"), và số "+N XP" là `RunState.last_run_xp` (XP thô của run, chưa qua trần ngày, chưa qua server). Màn Pass thì đọc `MetaState.pass_season` + `PassV2`. Hai nguồn khác nhau.
- Sửa: thêm `godot/scenes/pass/pass_summary.gd` (`PassSummary`), một chỗ đọc duy nhất từ Pass v2: tên, level, XP trong level, phần thưởng level kế. Cả Result và Pass dùng nó. Result bỏ pill "+N levels" cũ. Số "+N XP this run" chỉ hiện khi chạy local và là phần thay đổi thật của `pass_season.xp` (0 ngoài mùa thì không hiện); khi econ remote (production) client không biết server cộng bao nhiêu nên không hiện số.
- Test: `godot/tests/t_result_pass_agree.gd` (18 check): ba trạng thái XP, so tên / level / dòng XP / phần thưởng kế giữa Result và Pass. `t_result_and_stage` đổi caption "LUNACIA PASS" thành "SEASON PASS".
- Không đụng thư mục có fingerprint, không bump RULES_VERSION.
- Tìm bởi: UX hunt 27/10.
