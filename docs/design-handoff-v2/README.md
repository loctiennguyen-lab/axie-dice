## Reading the `.dc.html` files

They render from a data block, so stripping the tags gives you `{{ mustache }}` placeholders
rather than content. Two ways in:

```bash
# the spec's own content — already extracted for you as spec-data.js
python3 -c "
import re,html,sys
src=open(sys.argv[1],encoding='utf-8').read()
print(html.unescape('\n'.join(re.findall(r'(?is)<script[^>]*text/x-dc[^>]*>(.*?)</script>',src))))
" "<bundle>/Godot Combat v2.dc.html"
```

…or just open the file in a browser. Every value in the three MOCKUPS is an inline style,
so the DOM is a readable list of real numbers.

## Owner decisions that override the handoff

| Date | Decision |
| --- | --- |
| 2026-09-20 | **Scrolling is permitted.** The handoff's Main Menu entry says "Nothing scrolls." That constraint pushed Pass and Unlocks off the menu — v1 had rendered both inline there — which made spending Gene Shard and claiming Pass rewards unreachable from the UI. The project owner lifted the constraint rather than accept the regression. Use a `ScrollContainer` wherever a list is genuinely longer than the screen, and call `DangoTheme.style_scrollbars()` on it; do not compress a layout or drop content to avoid a scrollbar. Every other redline still applies inside the scrolled area. |

## Open questions the mockups do not answer

**The lead Axie and a same-lane node collide (Run Map).** The design puts the party's lead Axie
on the current node at 132px with its feet on the token's top edge, and sets the row pitch at
118px. Those two numbers cannot both hold when the node directly above the current one is in the
SAME lane: a 132px sprite standing on a token reaches 14px past the next row. The mockup's static
fixture never shows this because its example puts every reachable node in one of the other two
lanes — but real generated maps produce straight columns often.

Currently the tokens draw over the Axie, so the Axie is the thing that gets hidden. That is the
safer of the two failures — a node is information and the Axie is decoration — and it is a
deliberate choice, not an oversight. The neighbour's caption chip is also geometrically inside
the current token's rect in this case and is hidden rather than misplaced.

A real fix needs a decision from the design side, not from code: shrink the Axie, raise the row
pitch, offset the Axie laterally when the lane above is occupied, or accept it. Do not "fix" this
by quietly changing one of the two redlined numbers.

## Capturing a screen — do NOT use `--headless`

`--headless` selects Godot's dummy renderer, and `get_tree().root.get_texture()` then returns a
null texture. A capture scene run that way does not fail with a clear error — it hangs or writes
nothing, which reads as "the capture harness is broken". This cost about 40 minutes on
2026-09-20 before it was diagnosed.

    # right — real Metal renderer, writes a real 1920x1080 PNG
    Godot --path godot res://tests/qa_<name>_capture.tscn

    # wrong — dummy renderer, null texture
    Godot --headless --path godot res://tests/qa_<name>_capture.tscn

`--headless` is still correct for every `t_*` test, which assert on state rather than pixels.

## The rule that settles arguments

**Where the spec and a mockup disagree, the mockup is right and the spec is wrong.** Say so
rather than guessing.

## Design resolution

1920×1080, against `STRETCH canvas_items / aspect expand` — which is what `project.godot`
was already set to. Every offset in the redlines is from the 1920×1080 root Control, so they
can be typed in directly with no conversion.

## What has landed so far

- **Step 1 · fonts and the Theme.** `assets/fonts/` (Baloo 2 display, Work Sans prose, OFL,
  see the LICENSE there), `resources/theme/dango.tres` generated by `tools/gen_theme.gd`, and
  `project.godot`'s `gui/theme/custom` pointing at it so every Control in the project inherits
  it — including the many built at runtime.
- **Step 2 · surfaces.** `scenes/shared/DangoTheme.gd` grew the v2 surface vocabulary
  (`PANEL`/`PANEL_DEEP`/`PANEL_ON_ART`/`PANEL_RAISED`/`WELL`/`CARD_CREAM`), the hard-shelf
  shadow, `INK_ON_PRIMARY`, class colours, node tones, and the background formula
  (`scrim_texture()`, `plate_material()`, `build_plate()`). `resources/shaders/plate_grade.gdshader`
  does the `saturate()`/`brightness()` half of that formula.
  `t_button_states.gd` was updated in the same commit — see the `UPDATED 2026-09-20` comments
  in it for which v1 assertions the v2 spec supersedes and why each replacement tests the same
  rule.
